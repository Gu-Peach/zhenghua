# LangGraph V1

The production graph has three Agent stages:

```text
pdf_to_images
  -> build_page_index
  -> classify_pages
  -> page_scan_loop
  -> normalize_and_deduplicate
  -> build_cross_page_tasks
  -> resolve_cross_page
  -> normalize_after_cross_page
  -> assemble_table
```

## Stages

1. `classify_pages` reads Plant Function and the drawing-local Page Number.
   It writes each rendered page to `pages/<PlantFunction>/<PageNumber>.png`.
   PDF physical page numbers remain in the manifest and diagnostics, but are
   not used as the drawing identity.
2. `page_scan_loop` scans each classified source page in Plant Function/Page
   Number order. It sends only the source image to the VLM. Same-page endpoints
   are filled immediately; cross-page rows keep their start data and references
   while `end` remains empty. It aggregates rows by `wire_number`.

3. `build_cross_page_tasks` is deterministic code after stage two. It resolves
   each connection's `Plant Function + Page Number + Column` reference to PDF
   pages and writes one task per unresolved connection. `resolve_cross_page`
   sends only that row's source page and indexed target pages to the third Agent,
   which fills the endpoint or returns `needs_review`. The table is normalized
   again after completion.

   A wire unit may contain multiple cores and multiple connections with the
   same line number. If a target page or endpoint cannot be confirmed, the
   connection remains `needs_review`; no later completion Agent guesses it.

The endpoint code vocabulary is limited to `X0`, `X21`, `X22`, `X23`, `X24`,
`X3`, `X4`, and `X5`. Raw terminal boards such as `XD3` remain in endpoint
data. The table voltage/terminal-strip field is normalized to the configured
seven-value vocabulary.

The `current` field is populated only when an explicit current or rated-current
value is visible in the supplied drawing images. It is not inferred from
voltage, wire number, terminal number, or device name. A source note such as
“从原理图获取” is not a current value.

## Outputs

Library mode writes:

```text
source/<uploaded.pdf>
pages/<PlantFunction>/<PageNumber>.png
agent/page-classifications.json
agent/drawing_index.json
agent/page-scan-checkpoint.json
agent/wire-units-checkpoint.json
agent/cross-page-tasks.json
agent/cross-page-checkpoint.json
agent/cross-page-results.json
agent/stage2-table.json
agent/plant-function-groups.json
agent/table.json
table.json
groups/<wire-unit-id>/records.json
groups/<wire-unit-id>/table.json
manifest.json
```

`table.json` is the backend output contract. It contains the exact eleven
headers required by the frontend:

```text
页码, 原理号, 电压等级, 起点代号, 起点描述, 起点端子,
终点代号, 终点描述, 终点端子, 电流, 备注
```

No XLSX is generated by the new page-agent path. The frontend can generate an
XLSX from `table.json` or the group-level table data.

## Run

From the repository root:

```powershell
pip install -r backend/requirements.txt
python -m backend.cli --agent-pdf path\to\drawing.pdf -o frontend\public\library\agent-job --agent-output-mode library
```

The graph checkpoints each page scan and each cross-page completion. Re-running
the same library job restores completed stage-two and stage-three tasks.
