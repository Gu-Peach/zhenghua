# ADR 0031：补全对话可返回初扫生成修正候选

2026-10-17，代码与离线验收完成；真实模型效果待用户复试。只读诊断确认用户纠正“终点在本页”后，当前completion模型仍ready=false，原已确认初扫未改变；“只处理当前stage”和“缺目标图不得生成”的约束使对话循环。扩大肯定词白名单无法修复状态未变化问题。

对话内部增加受控revise_scan动作：用户指出已确认初扫的端点/同跨页判断有误时，加载原初扫原图、原结构化结果和用户原话，回到scan生成待确认候选，不自动提交或更改生产规则。分类确认保留；初扫/补全确认及过时补全候选按既有依赖失效规则清除。下一次用户明确接受修正候选后才保存初扫。

修正同页误判不要求用户再上传同一原图或虚构目标页；真正跨页连接的补全仍要求真实目标图。若新初扫已没有跨页引用，明确说明需另提供真实跨页样例以验证第三阶段，不重复追问这条同页连接，也不绕过既有发布校验。

模型输入将用户纠正独立提供，明确其优先于模型旧候选；反复的“同意”不被自动当成整个阶段提交。公开API/业务表不变，旧草稿通过下一轮对话应用新路径，原历史不直接修改。离线Fake/浏览器验证回退、确认、依赖失效和跨页正常路径。

## 补充：用户更换原图的身份边界

后续只读排障发现：用户明确换了原页，模型选择新图，但revise_scan仍强制使用旧图，造成description与结构化Expected不一致。现区分同图纠正和换图重扫：同图保留原Expected与纠正；换图采用用户在scan/completion提供的人工上传图片，重新初扫，不继承旧图页号、端点、引用、负例或Expected。用户必须重新确认新候选，分类确认保留，下游按原机制失效。

普通补全不得静默用不同原图执行：模型选中另一张用户提供的原图时转回scan，无法证明属于本次原图输入的图片不改变已确认来源。对话在生成补全前核查结构化references；没有任务时明确说明需重建初扫，聊天描述不能代替任务。内部动作可增加replace_scan_source，兼容已有revise_scan返回新原图的响应；公开API/表结构及发布门禁不变。

执行顺序已完成：先复现旧图覆盖和无任务错误，再修正路由/Prompt；22项对话、7项Wizard、1项既有浏览器阶段切换冒烟及Ruff/2源码mypy通过。实际草稿保持只读，由用户加载新代码后重新生成和确认。结果记录见[换图交付](../service/agent/changelog/2026-10-17-profile-source-replacement.md)。
