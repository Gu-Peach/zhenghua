# ADR 0032：现有规则的手动与Agent辅助编辑

2026-10-18，代码与离线验收完成，新迁移已部署明确的本地库；实际8000/8100需用户重新加载，真实模型诊断效果待试用。用户明确要求在Extraction Agent的“查看规则”内双击内容编辑、旁侧聊天辅助，根据规则/少样本/上传图片及实际提取结果诊断，用户同意后修改并发布新版本，入口替换旧版本并减少旧包占用。

复用ProfileAgent工具Graph、DraftStore修订/摘要/审计与发布校验。Server验证规则所有权，下载并校验已发布包或打包本地资源，以可信内部输入让Agent建立带来源ID/版本/摘要的编辑草稿，不能由浏览器直接指定Storage或本地路径。未修改Expected继承原确认；手动写入与建议确认均经过同一草稿写入校验。规则/答案变更展示diff，用户审核后确认当前修订再发布；不把用户实际识别结果自动当成人工Expected。

Agent每轮加载最新草稿规则和代表少样本，优先本轮上传图片；用户输入和结果作为观察证据，工具可继续看图/读文件。编辑入口强制讨论/建议模式，即使用户说“直接改”，模型也先提出可审阅建议；用户确认具体proposal和修订后应用。手动保存本身是用户明确授权，只作用于隔离草稿。沿用公开工具事件和流式回复，不新建Agent或端口。

新版以新版本号和新摘要发布，数据库事务检查来源版本仍为当前版本、用户所有权与幂等性。规则列表只展示同key最新版本。旧版本被现有项目引用时保留固定版本数据/资源；未被项目或任务引用的旧登记可移除，随后清理对应不可变Storage包。先登记新版再清理，清理失败不得把成功发布报告为失败；重试可继续回收。不得原地覆盖同版本包或破坏任务冻结副本。用户要求的“替换旧版”按可选规则入口替换实现，历史项目不偷偷换规则。

需要新增受信导入、编辑状态/写入/建议确认/验证/公开流代理契约及替换发布RPC；Schema迁移只增加新文件，既有发布RPC保持兼容。浏览器只经8000，8000经内部身份访问8100。修改业务Schema须在空库/旧快照隔离测试通过，再部署明确本地目标；不代为修改/发布用户规则进行验证。

实施补充：已有ZIP先完成库存/摘要校验，再在新草稿中更新程序维护的Schema；可被当前模型接受的旧Expected保持原事实，不能兼容时明确拒绝。旧包不改写，升级有可见提示；恢复草稿时的协议升级产生新修订并要求核对。回收使用持久队列和退役引用标记，避免失败丢任务及旧包重新登记与删除竞态。并行提取端改动保留，规则编辑不会写业务提取结果。

## 诊断证据补充

现有EvidenceAnchor只有path/quote，原实现统一用文本read_file验证，在图片或用户结果上必然失败。保持DTO形状兼容，明确证据定位约定：当前草稿.md/.json/.txt按原文逐字核验；图像路径只允许本轮实际查看过的当前草稿图片，quote为待用户核对的视觉观察，不冒充OCR逐字证明；user_message/observations/<索引>按本轮用户输入精确定位，用户陈述单独不能作为确定归因。工具结果公开证据来源/核验方式。

record_diagnosis和propose_edits持久化共用同一校验器；Store在相同修订下再次验证，查看图片/观察上下文由受信宿主提供，模型不能自称已看图。越界、未查看图片、伪造原文、错误观察索引继续拒绝，给出可恢复错误说明。记录诊断不是提案的强制前序；历史失败不代表新一轮工具不可用，不能反复要求用户开启权限。未授权的修改/发布约束保持不变。
