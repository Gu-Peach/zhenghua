# ADR-0036 重扫按范围替换

状态：代码、离线验收及本地新迁移完成，需重载服务后新建任务。用户2026-10-19明确要求“全部重扫替换全部范围；局部重扫只替换局部”。替代ADR-0034中全量未匹配旧行保留/新增的合并语义。

1. 已完成：契约和候选。fields=all且scope为页/工作区/PDF页集合时，程序设置result_mode=replace_scope；按行ID/原理号或单侧字段时为patch。模型不决定删除模式。全量候选包含全部待删旧行及全部新结果；只有全部目标页成功完成扫描才生成，空结果明确展示删空范围。候选生成不改业务库。
2. 已完成：新增迁移，确认时锁项目/任务/范围并核对批次、索引、整组行版本、完整待删清单；同一事务物理删除旧范围并插入新结果。沿用原确认的字段/坐标/来源验证，失败全部回滚、重复确认幂等。删除触发器不得误清除正在确认的任务。范围外数据不变；保留本次确认审计，普通手工删除的清理约定保持。
3. 已完成：前端显示删除/写入数量及完整可分页对照，空结果删除也须确认，拒绝不改库。旧版全量未确认候选禁用，需重新扫描；局部修订继续保留行ID。整范围替换产生新行ID，当前行已删除时重置解释会话到所属页，保留对话展示但不再查询旧ID/复用旧附件。
4. 已完成：Fake/Mock、隔离SQL（含有旧数据的迁移与全量删除/空结果/回滚/权限/并发）、浏览器和类型检查；更新README/交付记录。未经确认不执行实际线表替换。

新增result_mode默认patch保持旧DTO可读；旧版大范围fields=all候选不允许沿用合并方式提交。新的replacement清单使用强类型DTO，模型只提供图面事实；Server从持久任务读取候选，不接受客户端替换内容。新的SQL事务复用既有私有patch确认函数的插入校验，旧基线仅在事务内部临时清空以避免删除清理触发器移除本任务，成功后恢复本次审计快照；异常回滚全部临时状态。

服务端确认前检查rescan_replacement_contract()能力，未部署/降级时拒绝新范围替换，避免旧RPC合并追加。前端必须先读到持久化完整候选（包括显式空值）才允许确认，不能只依据SSE中的摘要。

验收：117项Agent Fake/Mock、24项API、21项新增隔离SQL及11项旧SQL、35项浏览器用例通过；类型/lint/build、Ruff及mypy通过。新增迁移20261019010000已在明确的本地库安装，三张业务表摘要不变，REST能力RPC返回1。未执行实际替换、创建真实任务、调用模型或重启用户服务。
