# Explain按用户意图发送

普通打开行/页来源解释窗口不再自动发送“解释获取链路”。界面显示当前范围与输入提示；点击发送或Enter后才提交用户需求，要求重扫可直接进入既有重扫候选流程。工具栏明确点击“重新扫描所选范围”仍提交一次重扫指令，不增加前置解释。

窗口挂载时生成新的conversation_id；关闭会取消当前流，重新打开不恢复上个窗口聊天。同一窗口追问仍使用同一会话，重试沿用原turn_id。数据库保存的待确认方案及按需打开的项目重扫记录仍可查看，不作为上一窗口聊天恢复。真实候选仍需确认按钮提交，API、后台会话存储、规则及数据库未修改。

实现位于`useExplainConversation.ts`的初始发送effect及`ExplainPanel.tsx`的空态。只有显式initialMessage触发初始化请求；长回复/修改卡在布局阶段跟随滚动，防止插入内容时的滚动事件误判为用户已离开底部。

验证：先增加普通打开/关闭重开的失败回归，再实现修复。37项Explain窗口、修改、重扫模拟浏览器测试通过；新增普通打开零请求、Enter/按钮发送、新会话ID、直接重扫单次请求和修改卡滚动三个场景各重复3次通过。另8项登录/工作台和失败、权限、长文本场景通过，桌面/窄屏截图已检查。TypeScript、lint与production build通过；构建仍有既有大chunk提示。第一次运行的3项失败分别为旧allow_rescan断言、长模拟回复未跳过逐字显示及修改卡滚动时序，已修正并复验。

本轮使用本地虚构HTTP/SSE夹具，无真实模型调用、重扫入队或业务数据写入；未测试真实模型的意图判断及Worker识别准确率。刷新Web后关闭旧窗口再打开即可使用，无后端重启或迁移要求。历史单次约5.5万字符事实包问题不属于本次优化，取消默认解释减少了不必要的首轮调用，不代表后续请求体已缩小。
