# PDF 上传弹窗卡片布局

2026-10-22，用户要求美化上传 PDF 时的规则选择界面。

原界面复用规则资源预览的固定大尺寸窗口，只有文件名和下拉框时仍占用大块空白。现在使用独立的 `upload-dialog` 样式，桌面最大宽度640px，高度随内容变化；窄屏单列，长内容在主体内滚动，保存区保持可见。

## 修改范围

- `apps/web/src/components/UploadDialog.tsx`：文件图标、名称/大小卡片，规则名称/版本单选卡片，选中高亮与勾选，后续处理流程说明，保存与失败状态。保留原有规则接口、规则键、上传参数、重试幂等键及200MB限制；不预选规则。
- `apps/web/src/assets/upload-dialog.css`：独立样式，不再继承可缩放资源窗口；两列规则卡片在小屏改为一列，长文件名最多显示两行并保留完整标题，多个规则局部滚动。
- `apps/web/tests/simple-management.spec.ts`：已有上传测试从下拉框选择改为原生单选控件，上传成功后的流程断言保留。
- 对话框增加初始焦点、Tab边界和Esc关闭；原生单选组支持方向键切换，保存期间按钮及规则禁用。

没有修改API、Agent、Prompt、提取流程或实际数据库/Storage；也未提交真实PDF。刷新Web即可查看。

## 验证

- TypeScript：`node node_modules/typescript/bin/tsc --noEmit --project tsconfig.app.json`通过。
- `npm run lint`和`npm run build`通过；构建仍提示主包大于500kB，不属于本次范围。
- 7项既有Playwright回归通过：上传保存、登录/工作台桌面与窄屏、空项目、加载/失败及权限状态。
- 忽略目录下的临时视觉检查脚本使用完全拦截的API夹具，检查未选择/已选择、规则加载/空/失败/无权限、重试恢复、保存中/保存失败、长文件名/15项规则、201MB文件阻止上传；失败重试复用幂等键，规则键正确。
- 覆盖1440px、390px及320×568小屏，共21张上传截图及布局断言；未发现横向溢出或底部按钮被裁切。目视核对正常选择、长文本小屏、空/失败/保存/超限代表截图，以及原登录/工作台桌面窄屏截图。
- 产物：`.runtime/upload-dialog-20261022/inspection.json`及截图，原回归产物位于`.runtime/simple-management-browser/`。这些均不提交。

沙箱内读取现有pnpm依赖曾出现EPERM及模块不可读；相同依赖在获准的沙箱外检查通过，没有安装/升级依赖或修改锁文件。
