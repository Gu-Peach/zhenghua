# 线表智能提取系统产品需求

> 状态：重构需求基线  
> 最后更新：2026-10-09  
> 关联文档：[总体重构方案](./refactor-plan.md)、[开发路线](./roadmap.md)、[待办事项](./TODO.md)

## 1. 目标

系统面向电气工程师，将不同标准的 PDF 电气原理图转换为可检索、可追溯、可修订和可导出的结构化线表。重构后不再以“任务文件夹”作为前端业务对象，而以“项目、工作区、图纸、线表记录”作为核心对象。

当前 PDF 上传、拆页、振华模板页面分类与三阶段提取已经具备原型能力。重构应保留这些能力，并逐步迁移，避免一次性重写提取核心。

## 2. 图纸标准

首批支持：

- 振华：样本位于 `case/zh`，当前规则和 Prompt 相对完整。
- ABB：样本位于 `case/abb`，放线标志为圆圈，需使用独立规则和 Few-shot。
- 其他模板：后续通过可插拔图纸 Profile 接入，不在公共工作流中堆叠品牌判断。

每个图纸 Profile 至少定义：

- 模板识别规则；
- 页面和工作区分类规则；
- 放线标志、端子及跨页引用规则；
- 三阶段 Prompt 与图片 Few-shot；
- 结构化 Schema、确定性校验器和输出映射。

## 3. 导入与拆分

每次上传一个 PDF 创建一个项目。导入后应提取公司、图纸标准、项目名称、工作区、图纸页号、PDF 物理页号和总页数等元数据。

PDF 每页渲染为一张图片，保留 PDF 物理页号。Agent 再按图纸标准识别工作区及图纸页号：

- 项目：一次 PDF 上传及其后续处理、反馈和导出集合；
- 工作区：图纸中的 Plant Function、功能区或同等业务分区；
- 图纸：工作区中的一页原理图，同时保留业务页号和 PDF 物理页号。

大型 PDF 可能包含多个工作区，例如数百页图纸；振华案例也可能只有一个工作区。拆分结果必须持久化到数据库，页面图片存储在对象存储中。

## 4. 提取与关联

系统按图纸 Profile 识别起点、终点、端子、线号和跨页引用。当前主流程继续采用阶段性提取：

1. 页面分类：识别工作区和图纸页号，建立图纸目录。
2. 当前页扫描：提取同页可确认数据，跨页记录只保留起点和引用证据。
3. 跨页补全：按索引加载来源页和目标页，补全剩余字段。
4. 确定性校验：归一化、去重、排序、字段约束和置信度检查。

线表按页面视觉顺序编号。每条记录必须保存来源页和证据，后续支持点击记录定位原图页，并高亮起点、终点及放线标志。

同一工作区内应建立线表连接拓扑；跨工作区连接使用独立的接口标识，避免与普通页内连接混淆。

## 5. 前端信息架构

### 5.1 登录页

- 使用 Supabase Auth 登录；
- 支持登录失败、加载中和密码可见性状态；
- 未登录用户不能进入项目页面。

### 5.2 应用框架

- Header：系统名称、当前项目、处理状态、通知入口和用户菜单；
- 项目顶部导航：线表工作区、图纸库、规则库；项目操作区提供 PDF 上传和结果导出；
- 左侧：`项目 -> 工作区 -> 图纸` 树形目录；
- 中间：线表结果、图纸证据、处理过程以及顶层图纸库/规则库视图；
- 线表终点为跨页索引时，鼠标悬浮高亮连接，点击后定位到索引目标图纸和端子；普通同页终点不呈现跨页交互；
- 右侧：Supervisor 主 Agent 监工面板；处理前为空态，显式开启“模拟链路”并上传 PDF 或发送自然语言请求后，才逐步输出淡化的主 Agent 思考文本、加粗的子 Agent 阶段、处理中等待标记和完成勾选；不另设顶部 Validation 阶段条；
- 主 Agent 接收自然语言修复需求后模拟查询线号与证据，依次分派结果查询、Stage 2/Stage 3 或规则归因链路。Mock 是显式触发的交互演示，不代表真实 Agent 已执行；答案可直接 patch Mock 线表，规则调整以候选版本展示，不直接发布生产 Profile；
- 上传 PDF 时先只在项目节点下登记源文件；Stage 1 完成后才展开工作区和拆分图纸，后续 Agent 阶段沿用同一事件流更新状态；模拟关闭时文件保持排队状态，不伪造处理进度；
- 用户菜单：切换账号、个人信息和退出登录。

### 5.3 管理体验

- 项目列表来自数据库，不再扫描 `frontend/public/library`；
- 展开工作区后显示图纸页，已处理、待复核、失败状态清晰可见；
- 线表支持筛选、排序、分页、行级修改和来源追溯；
- 图纸库按项目呈现图纸文件夹，规则库分别呈现 ZH 与 ABB Profile 及待审核候选；
- 只有跨页索引终点可悬浮高亮并跳转到目标业务页；
- 导出基于数据库中的某次结果快照生成，保证导出内容可复现。

## 6. 用户反馈与规则演进

用户可对单条线表、单张图纸或整个工作区提交修改和建议。修改分为两类：

- 数据修订：直接修正项目结果，保留修订前后内容和操作者；
- 规则建议：进入规则改进队列，形成候选样本、Prompt 或校验器变更。

生产 Agent 不应直接根据单次对话自动改写规则。规则变更必须经过案例回归、版本记录和人工启用，防止一个项目的修复破坏其他模板。

## 7. 可观测性与异常处理

- 处理过程以本次运行事件流展示，包括拆页、分类、页扫描、跨页补全、校验和落库；首次加载不得展示预置历史 Agent 过程；
- Supervisor 事件流需区分淡化流式思考、阶段 Agent、工具、结果和错误；Mock 链路必须由用户显式开启，真实运行事件待接入 API/SSE；
- 支持失败重试、断点续跑和取消任务；
- VLM 不确定或字段缺失时标记 `needs_review`，不得编造终点；
- 每个阶段保存结构化产物，便于定位是分类、页扫描、跨页补全还是校验问题。

## 8. 验收标准

- 用户登录后只能看到有权限访问的项目；
- 上传一个 PDF 后自动创建项目，并形成工作区和图纸树；
- 页面刷新后仍可查看处理进度和历史结果；
- 前端能从数据库读取并分页展示结构化线表；
- 每条线表可追溯到来源图纸和处理阶段；
- 能从指定结果版本导出 XLSX；
- 新增图纸标准时不修改公共 Graph 拓扑，只新增或扩展 Profile；
- 用户修订有审计记录，规则建议可进入离线回归流程。
