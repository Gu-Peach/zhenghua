# 混合纠错起点匹配修复

## 原因

test0 混合纠错运行 `d424b1e2-de7f-4e01-aa93-5a664f5aa594` 在跨页 Stage 2 完成后失败。
数据库 `start_code` 是展示投影，可能保存位置（例如 `+01F11.3`）；Stage 2
`start.device` 则保存设备（例如 `-XD3`）。旧匹配直接比较二者，同页目标被静默跳过，
跨页单条目标抛出 ValueError。Worker 仅返回笼统 INTERNAL_ERROR，没有记录异常位置。

## 改动

- `tools/extraction_runner.py`：使用独立的位置、设备、端子排和端子身份；优先读取保留的
  `start_location/start_device/start_terminal_board`，兼容嵌套 endpoint 及展示投影。
  支持设备标记 `-`、大小写/空格、`XD3:260` 与独立端子排＋端子形式，不把位置与设备混为一谈。
- 保留源起点和稳定连接 ID，仅替换授权字段；不修改传入的模型输出或原始记录。
  不再通过“只有一个结果”猜测身份，也不使用列表首项代表目标。
- 已知位置缺失、起点不一致、目标未找到、重复输出和歧义匹配明确报错，不生成不完整的修订。
  已有 `MODEL_SCHEMA_INVALID` 错误码用于模型输出的起点一致性校验，消息解释具体问题；
  不新增公共 Schema、接口或 migration。无法匹配时不能提交，也不能将空修订当成成功。
- `application/worker.py`：非持久提取协议的意外异常日志包含 run ID、阶段、异常类型和
  调用帧文件/函数/行号；不输出异常正文、源代码行、局部变量、模型内容或凭据。
  API 对未知异常仍返回安全的 INTERNAL_ERROR；已分类的匹配异常返回具体安全消息。
- Stage 2/3 Agent、Prompt、Profile 包及完整 PDF 提取算法未改。

## 验证

- 修复前新增的 10 项匹配回归全部失败，可复现同页遗漏、跨页 ValueError 及错误身份保护问题。
- 修复后 33 项相关离线测试通过：匹配/缺失/歧义/重复、Stage 2→Stage 3 目标页调度、
  起点保护、批次、Supervisor 链路、完整提取 Worker 和安全异常日志。
- 修改文件 Ruff 检查通过；Agent 全包 strict mypy（158 个源码文件）通过。
- 只读加载本次任务已经提交的 Stage 2 产物和反馈 bundle，在内存重放匹配：
  `XD3:260` 得到终点 `1`；`XD3:113` 得到跨页状态与 `006.C/1` 引用，不再抛异常。
  后者重放不执行真实 Stage 3，不声称已经识别最终终点或完成规则归因。
- 未调用真实模型、未写数据库/Storage、未重启服务，测试数据仍保留用于用户验收。

## 用户重试

1. 手动停止并重新启动原来的 API/Worker，让进程加载修复；若 Worker 独立部署，也要重启对应 Worker。
2. 保留现有三条注错数据，不需要再次注错。
3. 重新运行原混合终端脚本和准备好的 message/expected，使用默认新会话。
   不传旧 `--run-id`：该参数仅监看，旧失败任务还包含修复前的局部 item 缓存，不能当成新验收。
4. 新任务展示最终 proposal 后人工确认，随后继续检验原位提交及 Improvement 归因。

完整真实模型混合链路和规则判定仍由用户重试验收；本次离线通过不代表这些步骤已通过。
