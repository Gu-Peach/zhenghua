# ZH2.0.3：起终点元件标识读取优先级

## 行为

按用户确认，ZH元件列的device不再用X/XD/XA/XH排号或原理号填充。同页读取端子附近/所属框体明确的元件标识，没有则回退该端所在页Object Loc；跨页优先读取对应导线引用的+对象标识，再读附近，最后回退本端所在页Object Loc。附近同时出现+对象位置和器件代号时选对象位置；没有对象位置但有明确实际元件标识时仍可读取，如-W1。

来源出页引用中的对象属于终点，目标对应线路回指中的对象属于起点。工作区、页号/列号及线路匹配名称分开保存，不改变放线段和实际端子的读取方法；初扫跨页end仍为空，对端对象保存于references.target_object。

## 修改

- ZH初扫/补全Prompt、调用指令与运行时Schema字段说明、rules.json同步；Profile版本2.0.3，manifest v7。
- 内部补全Data/Result增加可选source_component(device/location/basis)。Graph仅应用来源元件/位置元数据并保留依据，起点端子/排号、原理号、方向和连接ID不变；旧响应无此字段保持旧行为。合同Schema与资源checksum按实际内容更新，公共HTTP路由和请求DTO不变。
- C01的-XD1元件改用本页+00，W1附近实际标识保留；C02用附近+02，不用页眉+00覆盖。M03/M23的XD3只作端子身份，元件分别读取+01F11.3、+01F10。两组补全同步：Q1端附近+02优先于目标页眉，FO2引用+01F42优先于TF41；目标回指+00可完善起点元件。
- 更新四份初扫expected、两份补全expected及任务上下文，不改变原理号、针脚、方向、连接数；接收段负例保留。仍为5组初扫、2组双图补全。新增来源元件完善不改端子/原理号的回归，并同步原有版本/字段预期与provenance。

## 验证与边界

仅完成静态检查：5组初扫/2组补全的manifest路径和Pydantic Schema、修改Python语法、资源checksum、ZH2.0.3只读注册绑定、git diff --check通过。遵照用户自行测试要求，未运行pytest、冒烟、类型检查、提取脚本或真实模型；实际提取效果尚未复测。

不修改ABB/XMZ的Prompt、策略或expected；新增可选结构兼容其旧响应。不写数据库/Storage、不发布/重绑生产规则、不启动或重启服务、不覆盖旧XLSX/运行结果。保留工作区其他任务已有改动。
