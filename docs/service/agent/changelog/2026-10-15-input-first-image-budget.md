# 请求图片预算优先保护实际图

用户要求优先保证当前待提取图清晰度，再压缩或减少Few-shot。实现改为按优先级分配：实际来源/目标图先在现有输入最长边上限内预留像素，案例使用剩余预算；先压缩案例，低于默认768px最长边下限才从末尾整组删除user图像/任务及assistant expected。允许无案例，双图案例不可拆散。只有实际图自身超过总预算才继续降采样，不放大、裁剪或改写原图，归一化坐标不变。

默认输入最长边2048px、总像素6000000保持；新增AGENT_MODEL_FEWSHOT_MIN_IMAGE_SIDE，原本比下限小的案例不放大。本地分组CLI额外双图预缩放默认改0，统一交给公共预算层；用户显式设置预缩放参数仍有效，0也不绕过公共预算。

公共请求metadata增加策略input_first_v1、案例保留/删除数量及原消息索引、输入图是否因总预算额外缩小；本地日志同步白名单，不保存请求图片/完整Prompt。完整PDF和分组入口的完成页指纹包含策略/图像配置，避免复用旧策略结果。所有模板共用此图像传输策略，未修改模板Prompt、expected或业务提取规则。

新增/更新离线回归覆盖输入优先、案例缩放、成对删除/顺序、双图作为整体、输入自身超限、消息/原图不变、长窄图和配置读取。按用户既有自行测试要求，未运行pytest、预算函数行为回归、真实模型或提取。

静态验证通过：7份Python AST语法；实际配置2048px/600万像素/768px；两个CLI --help独立加载；预算模块strict mypy、预算模块及其回归文件Ruff；diff空白检查。同步ZH资源元数据中本次修改代码的摘要，不覆盖其他未提交改动。不写数据库/Storage、不发布规则、不重启服务、不覆盖旧结果；未验证真实请求/模型准确率。
