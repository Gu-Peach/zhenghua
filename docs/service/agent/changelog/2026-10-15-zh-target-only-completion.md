# ZH 目标图定向补全

本地 ZH 2.1.0 / manifest v11。设计见[改造方案](../zh-target-only-completion-plan.md)。未发布到远端、未写数据库，也未运行提取/真实模型/pytest。

## 改动

- Profile `extraction.cross_page_input_mode=target_only`，公共默认仍为 `source_and_target`；ABB 1.1.4、XMZ 0.1.2 的规则、Prompt 和图片样例不变。
- Graph 从初扫 state 和页面索引保留来源/目标业务工作区、页码、Object Loc；ZH 客户端声明不使用来源图，补全节点跳过来源 payload 加载。工作流仍逐页初扫、定向补全、校验、保存，没有新增阶段或批量策略。
- 初扫新增可选 `signal_name`，只存对应导线/箭头旁可见名称；原有页级字段和 references 保留。输出映射带入任务和 JSON，不增加 XLSX 列，不改变放线标记优先的识别步骤。
- ZH 适配器把任务投影为版本化 Pydantic 来源事实上下文，只发送目标图。目标回指、原理号、线路/信号名、对象与页列共同匹配，再沿线读最近实际端子。缺少唯一依据则留空复核，不自动回退双图。
- 已存起点端子、坐标、原理号和方向沿用原有合并边界；已有电流通过响应归一化保护，模型新值不覆盖。可选 `source_component` 仍只补来源元件元数据。图片 metadata 记录补全输入模式。
- 3 组原跨页正例改为目标图加结构化来源事实，端点、坐标、电流预期不改；增加 003C01 三条同原理号 N 线且来源身份缺失的负例。保留 5 组初扫、8 张既有图片，不增加或修改图片。
- 同步扫描/补全 Prompt、manifest、checksum 和回归文件。本地分组 CLI 的补全预缩放状态改为由调用阶段决定，不再依赖是否传入来源图，参数不变。

## 验证与限制

静态核对通过：14 份 Python 语法、变更 JSON 语法、9 份源码 mypy、5 组初扫/4 组补全的 Pydantic 任务/expected Schema 与图片路径、三模板只读绑定、两入口 CLI `--help`、provenance 全部摘要及 diff 空白检查。新模块与新回归文件 Ruff 通过；所有变更 Python 相比 HEAD 无新增 lint（保留既有 16 项）。回归文件补齐目标图输入、来源事实、缺失来源图片、已有电流保护、坐标保留及模板模式隔离，但没有执行测试。

provenance 同步本次文件摘要；另发现上次统一主表后遗留的 `excel.py` 摘要与当前未改动代码不符，本次只读核对后更新该摘要，未改导出实现。

实际精度、模型视觉负担和耗时仍待用户用新目录、新 run_id 复测。减少图片不能修复初扫已经读反的方向或遗漏的原理号/引用；那些事实会原样传给补全。来源业务身份缺失或重复原理号无法区分时，留空可能增加。
