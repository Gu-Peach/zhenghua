# Profile Agent 引导式规则对话

2026-10-17。设计见[ADR-0029](../../../adr/0029-profile-conversation.md)。代码和离线验收完成，真实VLM效果待用户验证；未启停运行服务。

`conversation.py`通过LangGraph编排理解/追问与生成/记录。模型读取当前阶段、当前候选、最近对话和真实附件，信息不足时只追问；信息充分时调用原ProfileWizard生成候选。分类解释工作区/业务页号及分页方式；初扫解释放线标记、起终点和引用；补全复用已确认初扫原图、起点及引用，读取目标页，冻结来源身份。

`prompts/conversation.md`定义逐步收集、纠正和权限边界。结构化决策与候选校验后，SSE传输公开答复和状态，前端逐字呈现；不传输原始结构化输出片段、图片Base64或内部思维过程。`StageCandidate.readings`保留每个案例的公开读图结论、放线标记说明和图纸证据步骤；实际提取输出Schema未改。

对话/幂等回执和候选或确认在同一草稿修订内提交，保存于原`.runtime/profile-agent`。草稿所有者、修订冲突、前序依赖和明确确认由程序约束。简单“确认/没问题”仅在上一轮确实生成当前候选时接受；对其他追问的肯定不确认旧候选。对话收集到一半再补充文字，继续使用已上传图片。保留最近120条消息及120个消息回执；模型使用最近12条和当前候选，长历史可恢复但不会全部传给模型。保存模型/耗时/重试/用量/输入图片和Prompt摘要。

原三步接口、独立诊断/编辑能力、发布门槛和提取规则保持兼容。生成不等于确认，也不自动发布；发布仍要求真实正例/负例等完整性检查。确认前可以聊天纠正或表格修正，之后才安装规则与Expected文件。原接口不依赖新增对话元数据，已有草稿可直接恢复进入当前阶段。

验证：8项新对话Fake测试、7项阶段向导回归、33项原Profile Agent/API测试及4项Server代理/契约测试通过；覆盖图片追问、修正承接、来源冻结、确认语义、重试、权限、恢复及公开SSE。3个修改Agent源文件strict mypy及源码Ruff通过。没有运行真实模型、写业务数据库或发布规则；模型对图纸理解仍需人工核对。
