# 规则发布负例改为可选

2026-10-17，按用户明确要求调整。设计补充见[ADR-0028](../../../adr/0028-profile-creation-publication.md)。

统一草稿校验器移除NEGATIVE_CASE_MISSING数量门槛，没有负例也可以通过校验、导出并进入手动发布。用户已提供的负例仍保留到案例manifest和规则包，图片资源、Expected Schema、语义和人工确认继续校验；负例不是忽略校验的特殊通道。三阶段确认、初扫正例、资源完整性、适配器和规则版本约束保持原行为。

对话结束不再提示必须补负例，模型策略明确不主动追要或编造负例；兼容表单入口改为“负例可选”提示。公共DTO、API、数据库Schema及提取器没有变化，业务Server继续调用Agent的统一校验和导出，不额外设置负例数量门槛。

验证先复现三阶段全部确认、只有正例时仍被NEGATIVE_CASE_MISSING阻塞。修复后5项校验、7项Wizard和22项聊天，共34项Agent离线回归通过；其中完整聊天测试验证仅有正例仍可导出，负例测试覆盖保留资源/答案、错误语义及未确认拦截。17项规则表单/聊天浏览器回归、前端类型/lint/production build、Ruff和2源码mypy通过，相关桌面/窄屏截图已核对。浏览器使用Mock API；未执行真实模型或真实发布集成，截图在忽略的`.runtime/profile-optional-negative-check`。

未调用真实模型、修改用户实际草稿/数据库、代为发布规则或启停用户服务。需用户重新加载8100并恢复原对话，以重新计算发布资格；不需要重做阶段确认。没有公开DTO或API Schema变化，不重新生成Client。
