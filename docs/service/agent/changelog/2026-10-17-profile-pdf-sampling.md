# 分类阶段PDF随机两页工具

2026-10-17。见[ADR-0030](../../../adr/0030-profile-pdf-sampling.md)。代码/离线验收完成；未运行真实模型或操作用户服务。

`pdf_sampling.py`提供可复用的`PdfSamplingTool.sample()`：校验用户草稿和修订，在内存打开PDF，读取页数后用SystemRandom无放回抽两页，只渲染选中页为最长边2048的PNG。默认50MiB；单页PDF只用一页并说明，不重复页。无效/加密文件明确报错；两张图都渲染成功后才调用repository保存。

原PDF、单页PDF副本和未选中页面均不落盘，也不写业务数据库/Storage；无需生成全册缓存再删除。草稿只新增选中页附件与文件摘要/总页数/物理页/附件ID回执。相同请求ID和内容重试返回同一抽样，不重新选择；内容变化拒绝。选中的证据及历史修订保留，不擅自清理用户既有图纸。

repository一次修订写入样图和抽样记录，重新上传PDF会清除旧三阶段候选/确认，保留历史。`Attachment.origin`区分人工上传与PDF样本；Conversation及Wizard均禁止初扫/补全采用PDF抽样页，要求用户上传对应原图和跨页图。旧附件缺少origin时默认人工上传，原图片分类入口兼容。

分类对话同时读取两张样图，形成共同分页理解；`StageGenerate.sample_images`只用于分类阶段，每张图分别生成案例及Expected，保留物理来源，不拿物理页号填业务页号。分类仍需人工确认，抽到封面/空白或依据不足时询问用户，不声称看过其余页。原提取Stage2流程未改。

验证：5项PDF工具测试及8项对话、7项阶段、5项Server测试，共25项相关回归通过；覆盖只渲染选中页、无原PDF文件、无效/加密/第二页渲染失败无新附件、单页、幂等、权限、独立业务页答案及禁止PDF样图进入初扫。原Profile Agent/API33项回归通过。6个Agent源文件strict mypy和Ruff通过。

只读渲染实际679页PDF抽中的物理页40/283，确认清晰与页边界，无原件副本；PNG位于忽略目录`.runtime/profile-pdf-inspection`。此检查未调用VLM或注册真实草稿。真实模型对两页概括规则的质量仍需用户核对。
