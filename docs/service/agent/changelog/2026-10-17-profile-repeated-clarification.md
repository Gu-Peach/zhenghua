# 修复同页纠正后的重复确认

2026-10-17。见[ADR-0031](../../../adr/0031-profile-scan-correction.md)。代码与离线验收完成，真实模型复试由用户进行。

只读核对草稿与私有模型响应：用户指出终点就在原页，且已回复确认/同意；这些消息确实被保存。模型连续返回ready=false、targets为空，继续索要同页“目标图”，原已确认初扫中的错误跨页字段未改变。根因是只允许处理当前阶段、第三阶段必须提供目标图的约束，与修正既有初扫事实冲突。扩大确认词白名单本身无法使状态向前。

新增内部DialogueDecision.action=revise_scan：补全阶段的初扫纠正请求可使用已确认的原初扫图片，返回scan重新生成候选；不需要目标图或重复上传。输入单独提供用户原话、原结构化初扫和修正上下文，用户纠正优先于旧模型说法。生成Prompt强调不同元件不等于跨页，本图两端确实可读时填写同页终点并移除误判引用。

生成修正候选按原依赖规则撤销scan/completion确认、清除过时补全候选，保留classification和原有已保存文件；只有用户接受新候选后才更新规则/Expected。用户说“同意/都同意/确认，同意”仅在它对应当前最新候选时可确认阶段；对澄清问题的同意不误提交旧候选。无对应初扫或未完成分类时禁止越级回退。

如果修正后原页没有跨页引用，明确说明本页连接无需再上传目标图；如需建立第三阶段，另提供真实跨页样例，不将原同页终点继续作为目标追问。没有跳过案例、人工确认或发布门槛，也不自动把默认规则标为已验证。

实现：`conversation.py`受控阶段回退与用户反馈上下文，`wizard.py`可选revision_context及同页证据要求，`prompts/conversation.md`定义修正动作与避免重复确认的策略。均为Agent内部协议，公共DTO/API和数据库不变，已有草稿下一轮可使用新路径。

验证：12项对话、7项Wizard、5项Server，共24项相关Fake/Mock回归通过；新增4项覆盖无目标图回退、旧循环中“都同意”恢复、禁止缺前序回退和已确认补全失效。11项规则聊天浏览器回归通过，覆盖回退后的阶段、端点摘要、不重复上传和确认；类型/Ruff/lint/build通过，桌面截图已检查。产物在忽略目录`.runtime/profile-clarification-check`。

未修改用户实际草稿/业务库、调用真实模型或启停8000/8100。需用户重载8100，使新增action与Prompt同时生效；可在原草稿发送“按刚才的同页纠正重新生成初扫候选”，无需重做分类或重新上传同一原图。新候选的实际读图准确性仍需核对。
