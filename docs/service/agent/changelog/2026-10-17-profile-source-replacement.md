# 修复更换原页后仍使用旧初扫的问题

2026-10-17。设计见[ADR-0031补充](../../../adr/0031-profile-scan-correction.md)。

只读核对草稿和本地模型响应发现：用户上传新原页及其跨页后，模型已选择新原页并给出对应描述，但此前revise_scan分支无条件覆盖source_image为旧初扫图片。保存的description因此描述新图，Expected却仍是旧图的同页连接。随后补全分支再次绑定旧初扫，触发NO_CROSS_PAGE_TASK。任务校验本身有效，错误发生在更换原页时没有重建正确来源的初扫。

`conversation.py`区分同图纠正和更换原页；`replace_scan_source`以及兼容的新图revise_scan/continue响应均先转到scan。可用新原页仅限用户在提取对话中提供且本轮已读到的人工上传图片，不允许把分类专用图、PDF抽样或目标图同时当新原页。新图不继承旧Expected、负例或旧图上传之前的纠正内容。生成后重新确认初扫，既有依赖失效机制保留分类、撤销下游确认；确认前不替换已保存规则文件。

跨scan/completion装载最近用户图片，支持从旧对话中的短句“同意”继续处理已上传的新原页；新候选确认后，对话纠正反馈也从当前原页的上传记录开始，避免旧图反馈再次干扰补全。补全前以初扫主案例的结构化references检查任务，无任务时返回具体引导，不以聊天描述虚构任务，也不发起无效补全调用。`wizard.py`仍冻结来源并保留任务门禁，生成Prompt补充换图时不继承旧图事实的要求。公开API/数据库/发布条件不变。

验证：先补Fake用例复现旧图覆盖和NO_CROSS_PAGE_TASK；修复后22项对话、7项Wizard回归通过。新增10种场景覆盖三种内部动作、当轮/历史/scan阶段上传、新原页确认后补全、重复请求幂等及无引用前置检查；断言不继承旧Expected和旧反馈。1项既有浏览器阶段切换冒烟通过，产物位于忽略的`.runtime/profile-source-check`；Ruff格式/检查、2源码mypy及diff检查通过。本轮没有前端生产代码或公开契约变更，未重复前端全量构建。未调用真实模型、修改实际草稿或业务库、发布规则或启停用户8000/8100/Worker。

用户需重新加载8100，在原对话说明使用已上传的新原页重建第二阶段，核对新Expected中的业务页号、起点与跨页引用并确认，然后使用已上传目标图继续补全。无需重做PDF分类。实际读图准确率仍需真实样图核验。
