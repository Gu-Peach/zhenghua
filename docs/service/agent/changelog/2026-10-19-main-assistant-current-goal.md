# 规则追问不再混入历史线表修改

## 现象

“开始修改”轮次已返回规则候选，用户通过按钮成功发布1.0.1；随后主助手额外请求线表修改，但只有项目范围，被Server按缺少工作区/页/记录拒绝。规则发布和该错误是两个不同动作，不能要求用户重新发布。

当前上下文把早前“修改数据然后更新规则”的目标带进短追问；专业Agent返回的长篇诊断正文又传入完成分类，可能使规则建议扩成新的数据修改目标。旧历史只有proposal_ready快照，没有动作当前状态，无法准确呈现已发布事实。

## 改动

- 完成分类明确以本轮需求为准；短追问仅延续最近相关话题，不累计历史复合请求。不把跨项目历史默认为执行范围。
- 专业Agent返回后分类不再传入其诊断全文；文字建议不是新增用户授权。
- 已有核验计划后，批量模型调用中额外的重扫/规则候选/线表候选/整文档提取工具若不属于本轮目标，跳过且不执行，不把无关失败传染给已返回的目标。真实复合需求仍保留全部工具回执校验。
- Server补充历史轮次范围、失败状态及数据库action当前状态；已发布规则包含最小发布版本引用，Storage路径和完整私有结果不进历史摘要。历史整轮失败不抹除其中成功的发布动作。

## 验证和启用

先补两项回归并复现失败，再修复；跨项目/同项目历史参数化覆盖、其他用户action过滤，以及诊断后夹带无关线表修改均通过。主助手与Server默认测试123通过、46项显式集成跳过；范围摘要调整后两项复验通过。Ruff、Agent七源码和Server两源码mypy通过，公开OpenAPI与保存文件一致。

无公开DTO、数据库Schema、前端或提取规则修改；未运行真实模型/浏览器测试或启停服务。本轮只读核对既有发布回执，不重复发布、不改历史失败轮次。重载8000/8100后生效。模型指代消解质量仍需实际对话复测。
