# 主助手重复检索与复合请求接续

真实失败轮次连续8次search_connections，其中7次用同一个原理号范围文本做精确检索。该轮没有调用数据修订或规则诊断，不能通过增加总轮数解决。

本次保留8轮总预算：

- search_connections新增显式principle_numbers数组，单值范围的解释由Server完成，模型应遵循真实返回编号。
- ReadProgress只在本轮复用成功的同参数只读结果，重复时暂时从工具列表移除对应读取工具。导航变更清理读取缓存；任务进度轮询不缓存。
- 短结构化核验返回全部required_tools。取得一个专业Agent回执后，仍需执行剩余目标，不能因为第一个答复为delegated就提前结束。
- 对用户明确给出的数字范围，已完整返回且不超过50条的实际记录可以绑定程序接续：限定真实记录ID，分别调用现有Explain proposal和Profile诊断，不猜修改后端子。不完整分页、空结果、无法绑定真实范围时不会自动扩大范围。
- 仍重复而无法推进时显示具体缺口并停止，不空转到笼统的8轮上限。
- 完成事件版本2包含每个必需工具的action引用；子Agent原文合并，仍保留各自候选与确认入口，不把生成候选描述成已写业务表或发布。

普通最终答复和专业Agent首次返回后都会用短分类判断复合目标；该分类不重写专业答复。没有真实模型测试，默认回归均为Fake Gateway/MockTransport。

本次17项主助手测试通过，包含原假重扫修复、范围重复后只检索一次并接续两个专业工具、空结果不重复查询8次，以及真实候选回执。Server与浏览器验证见[Server记录](../../../service/server/changelog/2026-10-19-main-assistant-progress.md)。重载8000和8100后重新发送需求。
