# Explain“正在读取图纸”假进度

## 现场与原因

用户给出U2/V2/W2/N四起点和XA:1—XA:4终点纠正线索并上传图片，要求重新识别。最近附件674×186、PDF52、创建08:20:35 UTC，会话150d8a89-f4bd-45cb-8b95-33c1d6d4647d；同会话诊断对应turn01581a5e-4552-42f1-949b-a63cb6f83b68，08:21:21结束，耗时43.709秒，finish=stop、returned_tool_calls=0，没有后续工具轮。数据库该会话重扫任务数为0。

因此截图 `[turn 4 tool call]正在读取图纸页002C06（PDF52）...` 是模型结束时的正文，不是尚在读取图纸或提取Worker卡住。现有门禁依据“已创建/已入队”等执行声称触发受控补调，漏掉了明确动作请求只返回读取计划的情况。此轮首调文本211854字符、上传图1张，也重复携带了嵌套历史证据；这不是已证实的模型故障或读取超时原因。

## 改动

- `rescan_receipts.py` 增加保守的直接重识别命令识别，排除流程/原因/状态/历史问句、引用和否定；它只用于要求模型完成动作，不从文本生成业务补丁。
- `graph.py` 对明确重扫动作的无工具终答复用一次受控required补调，继续遵守权限、8次工具预算、真实回执和确认门禁。没有回执不能用“正在读取/稍后处理”完成请求；持续无调用则明确失败。旧无回执缓存也不能满足动作请求。
- 动作规划正文暂不推给用户，工具事件和真实回执提供进度。普通只读终答伪装tool-call或仍在读图时返回EXPLAIN_TOOL_NOT_EXECUTED；不后台自动执行任何修改。
- 动作首调/后续检索只发当前完整字段、真实ID/版本、图纸目录、查询分页和本轮附件，不重复历史原始evidence及嵌套候选。完整授权来源证据、版本指纹和前端来源展示保持；普通来源解释不裁掉历史依据。
- 结构化兼容模式的clarify也拒绝假进度正文。Prompt明确要求实际工具调用或确实缺少信息的澄清，不模拟turn/tool-call日志。

设计见[动作完成约定](../explain-action-completion.md)。无DTO、Schema、Profile或Web变化。

## 验收与生效

四项缺陷回归先复现失败。148项相关场景分批通过，其中最终61项覆盖假进度/口头应答、一次补调失败、无权限/否定/普通解释、旧缓存、required不支持降级与真实回执、动作检索精简。12万字级别假历史证据下，Fake模型首调事实保持在25000字符内，后续检索消息在35000内，ID和分页保持；没有把用户预期终点直接写入数据库。

Ruff、三个源码严格mypy通过。未运行浏览器、全仓或真实模型质量测试；本轮没有Web改动。未创建实际重扫、修改实际任务/线表、调用真实模型或启停服务。只读确认8100 PID45256仍为15:22启动的旧进程；重载8100后重新发送该问题生效，此次无需重启提取Worker/8000或应用迁移。旧聊天正文不会自行变为真实进度。
