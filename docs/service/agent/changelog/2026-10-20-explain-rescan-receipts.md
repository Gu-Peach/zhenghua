# Explain 重扫任务回执校验

## 现场核对

用户反馈：起点 XA:4、XA:5、XA:6、XA:7、PE-bar 的终点应在本页，要求重新沿线提取；Explain 仅显示检索完成，却回答已创建“仅重扫终点”任务、状态 queued，并描述了目标页和端子。

本轮只读核对 `connection_rescan_runs`：最新任务创建于北京时间 2026-10-19 22:26:46，状态 ready；没有 10 月 20 日新入队任务。当前两份 Explain 诊断（北京时间 11:50、11:51）均正常 stop，`tool_result_messages=0`、`prior_tool_names=[]`、`image_count=0`。初始上下文读取显示的“检索完成”不能证明调用了重扫工具。此次问题是没有执行工具却宣称入队，不能归因为 Worker 排队或模型服务异常；回复中的目标页/端子也不能视为重提取结果。

## 修复

- 对常见的已创建/已提交/已入队/已完成重提取话术核对本轮真实工具回执；无依据的流式文字使用既有 `answer_reset` 撤回。
- 用户允许重扫时最多补调一次，只开放重扫、精确检索和看图；工具仍未执行、回执失败、只读模式或预算用尽时明确失败，不制造任务/候选。
- 当前轮成功执行的任务ID独立保存于会话缓存；其他轮次的历史任务不为新请求充当回执。重复相同 turn_id 读回真实任务，不重复入队；状态和阶段变化使旧答复失效。
- 已有任务的显式只读查询可使用对应数据库回执。任务答复使用真实 UUID/status/stage，queued/running 明确提示正式线表未改动及候选未就绪，模型编造的终点值不进入最终答复。
- Prompt 明确：本页纠正不能照抄旧跨页引用，预期端子不等于识别结果，无回执不得声称 queued。

改动集中于 `graph.py`、`rescan_receipts.py`、`service.py` 和 Explain Prompt，无 DTO、OpenAPI、数据库、Profile 或前端变化。沿用 ADR-0034/0041 的入队与候选确认契约。

## 验证与启用

- 先增加 5 项 Fake HTTP/模型复现测试，旧代码全部失败；随后扩展为 17 项，覆盖补调、失败、只读、历史隔离、缓存重试及否定/引用语句。
- Explain 相关 127 项离线测试通过，Ruff 通过，3 个修改源码 strict mypy（`--follow-imports=silent`）通过。直接递归检查依赖仍报告 5 个未修改依赖文件中的 14 条类型错误，本次未改这些文件。
- 未调用真实模型、创建实际重扫任务或修改正式线表；没有重启现有服务。未运行真实提取、数据库写入集成或浏览器验收，本轮没有变更这些路径。

需重载共享 8100 HTTP 服务以加载 Graph 和 Prompt，关闭再打开 Explain 窗口后重新发送需求；原来只有文字的“queued”没有真实任务可恢复。出现真实重扫工具记录和任务卡后才表示入队，候选仍需用户确认。本轮不更改 Worker、8000 或启动命令。
