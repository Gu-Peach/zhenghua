# 目标页误带源工作区：入队前校验与失败事件修复

## 现场事实

只读核对任务 `4442f030-95d2-5997-a7cc-9a2f39abb559`，源页002C06/PDF52，9行仅补终点。请求前5行绑定002C11/002.C/PDF53；后4行绑定002M03，但目标workspace_code误填为002.C。当前项目目录、任务冻结目录和阶段分类产物均唯一指向002M03/002.M/PDF56。

Worker原来把业务页、工作区和物理页求交后统一报告“未唯一定位”；实际是模型传参冲突，不是用户业务页号错误。任务status/stage均failed，checkpoint仅configuration，尚未进入端点模型调用。截图中的queued为入队回执文字，后续应以任务卡实际failed状态为准。

## 实现

- `rescan_targets.py` 提取 `resolve_target_page`，分别返回不存在、多个候选和显式限制冲突；冲突列出本项目真实目录页/工作区/PDF，不静默放弃约束。
- `repository.py.start_rescan` 在授权后用项目完整目录检查目标绑定，错误以 `RESCAN_TARGET_INVALID` 返回Explain工具，在持久化排队前拦截；Worker仍在冻结目录复核。
- Explain Prompt/工具参数说明把源scope与目标binding分开，目标页独立检索，不继承当前工作区；已返回唯一目录信息时按工具反馈修正参数，无需让用户重复提供正确页号。
- `graph.py` 修复“成功回执带error:null也发tool_failed”的判断，按实际错误值发出事件。Fake链路覆盖先失败、按目录纠正、只入队一次、成功事件正常的全过程。

不改DrawingProfile、公共DTO、数据库Schema或已保存任务；无需迁移、8000/Web变更。设计见[目标页校验](../rescan-target-validation.md)。
