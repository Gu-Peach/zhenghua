# 提取复核后处理计划

2026-10-16，用户确认最终review由程序判定，并明确本次同时实现上传即提取、逐步写库及前端实时展示。先完成复核契约，再接入三表持久化与前端。

## 设计

- VLM只提供识图事实、路径依据和结构化uncertainties，模型请求Schema和Few-shot隐藏status/needs_review/review_reasons等程序字段；兼容读取旧响应但不采信模型的最终裁决。
- 统一后处理计算needs_review、带code/field/message的review_reasons和processing_status；模型不确定性是规则输入，不能覆盖程序发现的问题。
- 初扫后存在引用且等待补全时保留pending_completion；缺少终点不是此时的最终缺失错误。页最终校验仍缺端点、引用不可用/回指、目标冲突、路径依据缺失才对应复核。
- Profile继续管理端子语义、方向证据及一致性约束；ZH、ABB、XMZ使用明确的选项，公共节点不按品牌分支。
- 缺电流/颜色/坐标/业务分类不单独触发review；不增加置信度阈值。技术配置/权限/持久化失败仍由任务错误处理。
- review信息同步到连接、扁平记录和页面汇总，保留页级与行级区别；初扫与页完成checkpoint含义不变。
- 公共领域契约升版并更新checksum；模型指令附加公共事实输出约束，Profile资产无需批量搬迁或发布远端包。旧status/needs_review字段保留内部兼容。
