# 提取请求图片尺寸控制

## 输入图优先修订（2026-10-15）

用户明确要求优先保证当前待提取图清晰度，再压缩或减少Few-shot。本节替代初版对全部图片共同降采样的分配策略，配置输入最长边/总像素上限继续有效，不自动提高供应商请求上限。

1. 来源/目标实际图先按输入最长边上限计算尺寸并预留预算，案例不再挤占这部分清晰度；双图的两张实际图都属于必需输入。
2. 案例分享剩余像素，允许等比例缩小；新增Few-shot最长边可读下限，默认768px，原本更小的图不放大。
3. 剩余预算不足以保留案例最低尺寸时，按现有案例顺序优先保留靠前案例，从末尾整组删除user图像/任务与assistant expected，不拆散双图案例或留下孤立答案；允许不带案例。
4. 所有案例删去后实际图仍超出总像素上限，才对实际图做必要的等比例缩小。原图、裁剪原点和归一化坐标含义保持，不做放大/裁切。
5. metadata记录实际/案例像素、保留/删除案例数与索引、实际图是否因总预算额外缩小及策略版本；日志不保存请求图片或完整Prompt。预算配置/策略进入完成页指纹，避免误用旧完成页。

本轮按用户既有要求只做静态语法/资源/配置检查，补离线回归但不运行测试/模型，不写数据库或覆盖运行结果。

修订文件已完成：7份Python语法、2048/600万/768配置读取、两个本地CLI独立加载、预算模块strict mypy及模块/预算回归文件Ruff检查通过；未运行pytest或图片预算函数的行为回归，真实发送尺寸和识别质量留待用户复测。实现与边界见[记录](./changelog/2026-10-15-input-first-image-budget.md)。

## 初版基线（历史）

2026-10-15用户授权补齐实际图请求缩放。原实现仅缩案例图，来源/目标原图直接编码，ABB双图补全可能超过服务端视觉patch预算。

在公共提取适配器组装单次模型请求时统一处理案例和实际输入，覆盖分类、初扫和跨页补全；不改变本地原图、图纸坐标原点或结构化结果。图片只等比例缩小、不放大、不裁剪。新增实际图最长边上限2048px和请求总像素上限6000000，案例仍受既有1800px上限控制；合计超限时对全部请求图片进一步等比例缩小。重复图片按实际发送次数计入，不假定服务端去重或缓存。

总像素是本地可控的保守预算，不声称等于服务商私有视觉patch公式；两个上限均可配置。模型请求metadata记录每张图原始/发送尺寸、图片总数、发送总像素及限制，便于调参。CPU图片处理在asyncio.to_thread执行，缓存的Few-shot数据不被原地修改。

案例的size_before是既有Few-shot最长边限制之后、请求总量限制之前的尺寸；实际图的size_before是磁盘原图尺寸。本地RecordingGateway同步保存vision_images/vision_total_pixels。内存/私有Trace仍按原边界，不新增业务库写入。

保留JSON Schema和重试行为，不扩大重试次数，不自动重跑付费提取。只做静态语法/配置检查，离线回归文件提供但按用户既有要求不运行测试或真实模型，不写数据库/Storage。
