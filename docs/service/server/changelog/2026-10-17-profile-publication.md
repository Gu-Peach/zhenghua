# 2026-10-17 Profile 鉴权代理与固定版本发布

8000新增Profile三步创建代理，Pydantic DTO由Agent生成，OpenAPI/TS同步。发布只接受草稿ID和修订号，经可信内部身份取得校验包；Server再次验证ZIP路径、大小、库存摘要及身份，再写私有内容寻址对象并调用新RPC。Storage成功而登记失败时保留可重试对象，不显示成功。

新增迁移 `20261017010000_profile_wizard_publication.sql`：按规则key加事务锁、key所有者、同版本不可覆盖、重复发布幂等；普通浏览器角色不能调用发布RPC或绕过发布插入storage引用。已发布身份/资源元数据不可修改。既有本地引用和项目固定版本保留。

规则列表、预览和上传PDF的规则选择同时支持Storage包，提取Worker按引用加载并冻结任务包。没有增加Agent端口或恢复旧业务表。

迁移在独立无网络临时PostgreSQL容器中，通过空库/带旧本地规则合成数据两种验证；容器和测试库已清理。未部署业务库，使用前需应用迁移并加载服务新代码。

环境记录：最初沿用现有Supabase容器内临时数据库的测试方式，权限异常分支触发该PostgreSQL进程SIGSEGV并自动恢复。已核对并移除唯一残留合成测试库，未修改项目记录；最终测试已改为完全独立容器并通过。该Supabase扩展环境的崩溃根因未定位，因此没有向业务库部署新迁移或再次在其上执行权限异常分支。
