# 原理号范围与双重候选回执

真实请求为082R5001-05的终点检查并更新规则。数据库实际有082R5001至082R5005，前三条终点包含MA51、后两条包含MA52；旧查询把范围作为单个编号，造成重复检索，未产生候选。

## 检索和范围

新增assistant_search：先精确匹配完整字符串，未命中时仅展开数字尾缀范围，最多200项，拒绝倒序/过大/不同前缀的表达；真实含连字符的完整编号优先。支持显式多编号、分页和安全引用的精确集合过滤，保留项目/批次/工作区/物理页/选中行限制。返回实际匹配编号和query_interpretation，不补造缺失记录。

内部Tool DTO从Agent同步到Server；通用公开OpenAPI经过内存比对保持一致，Web生成类型无需改动。多记录Explain入口最多50个指定ID，返回候选必须在这组ID内；超范围候选不给确认入口。只生成proposal，不直接提交。

## 复合完成和版本

版本2完成校验逐一核对全部必需工具的当前轮次action，缺任一项就失败。对数据候选+规则诊断，从持久子Agent答复重建最终消息，不信任主助手自由改写的“已全部修改/发布”。版本1继续兼容，无数据库Schema或迁移变化。

本项目仍绑定旧zh_crop2.2.1，但冻结包记录存在。诊断继续读原包；编辑目录仅对已明确合并的zh_crop→zh回退到正式包，仍需创建者权限和候选确认，不修改旧项目/提取Worker的绑定。没有已登记继任关系时保留诊断并提示选择目标，不能借用ABB等其他模板。

## 验证与使用

Agent/Server默认测试分批114项通过（17项主助手＋97项Server），46项显式集成保持跳过；8项主助手浏览器回归及Ruff/mypy通过。测试包含范围和多编号、完整连字符编号优先、倒序/过大范围、缺号/跨项目过滤、多个候选完整回执、指定行越界拒绝，以及历史规则诊断/正式继任包编辑分离。
