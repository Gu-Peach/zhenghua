# Stage 2内部节点：定向连接补全（ZH 2.0.5）

接收来源图、目标图和task_context指定的连接，补全该放线段尚未读取的终点信息。

1. 根据来源图的出页引用、原理号和目标图的对应入页线路，定位同一放线段。从目标图的对应入页箭头沿实际导线读取，遇到的第一个实际端子就是终点，不穿过该端子继续追到下游设备。引用中的线路名称用于匹配，不用于猜实际端子。
2. 元件对两个端点分别按“对应导线引用中的对象标识→该端附近/所属框体的元件标识→该端所在页Object Loc”读取。来源图出页引用中的+对象属于终点，目标图对应线路回指中的+对象属于起点。例如=046.R+01F18/1.1中的终点元件是+01F18；对应回指=003.C+01F11.1/2.1中的起点元件是+01F11.1。工作区、页号/列号、线路匹配名称、原理号和X/XD排号都不是元件。
3. end.device填写终点元件标识，end.location保存终点所属对象位置；两者可以相同。附近同时有+对象位置和器件代号时取对象位置；没有对象位置但有明确实际元件标识时可读取该标识。起点回退只用来源页Object Loc，终点回退只用目标页Object Loc；缺少某一依据继续下一优先级，全部不可读则留null。name只读取可见描述。
4. 读取目标端子实际排号/接口和端子数字。同排附近有明确X/XD/XA/XH标识时，其他数字也继承该标识，terminal完整写成XD3:109、X1:6等。terminal_board是实际排号，terminal_code是接口标识；端子读取方法不因元件字段规则改变。
5. 只补任务指定的连接，保留起点端子、原理号和方向。如两图可按上述优先级确认起点元件，使用可选source_component返回device、location和basis（指出引用/附近标识/Object Loc的图像依据）；它只补来源元件元数据，不返回或改写完整start。无法确认时source_component=null。引用用于定位，不从地址或相邻元件猜针脚，不按功能编号预先排除。
6. terminal_strip由程序按两端XA/XD/XH映射，模型不推测，相关字段留null。
7. 找不到目标、循环引用或图中信息不清晰时，无法确认的字段留null，保留可确认的部分并设置needs_review。正常的来源回指可用于匹配。
8. 端点与坐标确定后，可再沿同一相线实际导线查对应断路器的电流标注，经过端子仅为读电流，不改变端点/坐标/方向。优先Ir，其次明确In/Ie；Ie:(0.7-1)*160A直接取原文160A，basis=Ie并保留完整原文，不计算系数或改取Set。需带A/mA/kA单位。N、PE、控制、通信、光纤不填电流；不取相邻回路值，不使用漏电动作值、分断能力、无唯一标注数值的范围或电压功率推算。来源已有current时输出current=null表示保留。
9. end.terminal_coordinates记录终点端子符号/连接点中心在目标整张图片上的归一化x/y（0到1，左上角为原点）和目标PDF物理页号，例如{"x":0.17773,"y":0.17302,"pdf_page_number":403}。使用实际目标图，不填写来源图、端子文字、引用地址或箭头的位置。页号来自目标图上下文，程序按实际输入绑定；无法定位时为null。来源起点坐标保持不变，source_component也不能改写坐标。

只输出符合CrossPageCompletionData JSON Schema的JSON，包含task_id、end、status、needs_review及可见信息。source_note可简述读取依据；不输出额外连接。
